# راهنمای ابزارهای کیفیت کدنویسی الشفا

این تنظیمات در ۱۹ نوامبر ۲۰۲۶ برای پوشهٔ پروژهٔ الشفا روی ویندوز آماده شد. هدف آن کمک به تشخیص زودهنگام خطا است، نه تضمین درستی طبی، امنیت کامل یا آمادگی بهره‌برداری.

## ابزارها و راهنماها

- **Vue (Official)، Playwright و ESLint** در VS Code نصب شدند؛ افزونهٔ **C#** پیش از این نصب بود. نسخه‌های دیگر افزونه‌های موجود دست‌نخورده باقی ماندند.
- پیکربندی VS Code در پوشهٔ `.vscode` قرار دارد. آن را با بازکردن ریشهٔ `eye-main` در VS Code به کار ببرید. با `Terminal > Run Task` می‌توان Typecheck، Lint و Unit tests را دستی اجرا کرد. این پوشه طبق `.gitignore` محلی است و به صورت پیش‌فرض با Git منتقل نمی‌شود.
- فایل `AGENTS.md` قواعد مهم کار روی پروژه را مشخص می‌کند و به مهارت محلی `.agents/skills/alshifa-safe-coding/SKILL.md` ارجاع می‌دهد. مهارت برای توسعه، بازبینی، امنیت، پرداخت‌ها و دیتابیس همین شفاخانه نوشته شده است. وجود فایل به معنی تأیید ثبت خودکار آن در فهرست مهارت‌های سراسری Manus نیست؛ در صورت لزوم مسیر فایل را در درخواست خود به عامل بدهید.
- ESLint و تنظیمات رسمی Vue/TypeScript به عنوان وابستگی توسعه با نسخه‌های ثابت در `frontend/package.json` و `frontend/package-lock.json` ثبت شدند. قالب ESLint در `frontend/eslint.config.js` قرار دارد. این تنظیم، فایل‌ها را خودکار اصلاح نمی‌کند و به دستور build اضافه نشده است.
- نسخه‌های اصلی موجود پروژه حفظ شده‌اند: TypeScript 6.0.3، Vue 3.5.44، SDK محلی .NET 10.0.403 و MySQL محلی 8.4.11. SDK سیستم به تنهایی نسخهٔ 8 است؛ برای بک‌اند از SDK موجود در `.tools/dotnet` و تنظیم ثابت `backend/global.json` استفاده کنید.

## دستورهای روزمره

در PowerShell، ابتدا به پوشهٔ `frontend` بروید:

```powershell
cd F:\eye-main\frontend
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run test:unit
```

پسوند `.cmd` در این ماشین مشکل اجرای `npm.ps1` را دور می‌زند، بدون تغییر سیاست امنیتی PowerShell. `typecheck` کدهای داخل `src` را بررسی می‌کند، نه همهٔ فایل‌های پیکربندی و تست Playwright. تست واحد فعلی دو سناریوی کلاینت HTTP را با پاسخ ساختگی اجرا می‌کند؛ پیش از اضافه‌کردن تست‌های جدید، مستقل‌بودن آن‌ها از دیتابیس را حفظ کنید.

برای بررسی نسخهٔ SDK بک‌اند بدون بارگذاری رمز یا اتصال دیتابیس:

```powershell
cd F:\eye-main\backend
& F:\eye-main\.tools\dotnet\dotnet.exe --version
```

خروجی این دستور `10.0.403` بود. استفادهٔ خودکار افزونهٔ C# در VS Code از همین SDK محلی هنوز در محیط گرافیکی تأیید نشده است.

## نتیجهٔ بررسی اولیه

- `typecheck` پس از نصب ابزارهای جدید موفق بود.
- دو آزمون مستقل HTTP موفق شدند. آزمون کامل بک‌اند، E2E و build بک‌اند در این مرحله اجرا نشدند؛ به‌ویژه آزمون‌های یکپارچه می‌توانند دیتابیس را پاک کنند.
- اولین اجرای Lint روی ۱۴۰ فایل، **۱۳ خطا و صفر هشدار** گزارش کرد: ۱۱ مورد تغییر prop در `DossierForm.vue`، یک عبارت استفاده‌نشده در `clipPlayer.ts` و یک import استفاده‌نشده در `SettingsPage.vue`. این‌ها یافتهٔ ابزار هستند و هر مورد باید در متن جریان واقعی برنامه بررسی شود؛ ۱۱ مورد prop الزاماً به معنی ۱۱ باگ مستقل نیست. هیچ اصلاح خودکار یا تغییر کد تجاری انجام نشده است. دستور Lint تا رسیدگی به موارد موجود با کد خطا پایان می‌یابد.
- ممیزی آنلاین `npm audit` در زمان بررسی برای وابستگی‌های ثبت‌شده صفر آسیب‌پذیری شناخته‌شده گزارش کرد. این نتیجه وابسته به پایگاه دادهٔ npm و زمان اجراست و به معنی امن‌بودن همهٔ کد یا بسته‌ها نیست؛ وابستگی‌های .NET با این دستور بررسی نشده‌اند.

## موضوع‌های مهم برای مرحلهٔ بعد

### ایمنی دیتابیس آزمون

`backend/tests/AlShifa.Tests/ApiFixture.cs` پیش از تست می‌تواند جدول‌ها را خالی یا دیتابیس را حذف کند. محافظ فعلی در `DatabaseSafety.cs` پسوندهای `_test`، `_dev` و `_load` را می‌پذیرد و به‌تنهایی هویت سرور یا شمارهٔ پورت را تأیید نمی‌کند. بنابراین صرف نام ظاهراً آزمایشی کافی نیست. تست‌های Sync علاوه بر دیتابیس، ممکن است کاربر MySQL در سطح سرور ایجاد یا حذف کنند.

پیشنهاد: در یک تغییر جداگانه، محافظ تست‌های مخرب و آزمون‌های مستقل آن تقویت شوند و برای Sync یک نمونهٔ کاملاً جداگانهٔ MySQL استفاده شود. تا آن زمان پیش از هر آزمون یکپارچه، سرور، پورت، دیتابیس، دسترسی‌ها و نبود اجرای هم‌زمان را مشخصاً بررسی کنید. دیتابیس نصب‌شدهٔ شفاخانه روی پورت 3308 هدف آزمون نیست.

### سیاست رمز عبور

در `backend/src/AlShifa.Api/Program.cs` حداقل طول رمز Identity برابر ۱ است و الزام‌های پیچیدگی خاموش‌اند. این یک ضعف تنظیمی قابل بررسی است؛ از آن نمی‌توان نتیجه گرفت رمز هر کاربر فعلی چیست. سیاست جدید باید با نیاز شفاخانه، روش ورود و حساب‌های موجود هماهنگ و سپس همراه با آزمون اعمال شود؛ در این مرحله تغییری در ورود یا رمزها داده نشده است.

### مستندات و دادهٔ حساس

بعضی اسناد قدیمی نسخهٔ آنلاین را فقط‌خواندنی توصیف می‌کنند، اما `docs/local-online-sync.md` و کد کنونی از درخواست‌های صف‌شدهٔ آنلاین در صورت پیکربندی پشتیبانی می‌کنند. فعال‌بودن آن در محیط عملیاتی در این بررسی تأیید نشده است.

در ریشهٔ این پوشه مخزن Git شناسایی نشد. پیش از راه‌اندازی مخزن یا اشتراک پروژه، فایل‌های پشتیبان، اطلاعات بیماران، تصویرها، کلیدها و تنظیمات محرمانه را جداگانه بررسی کنید؛ `.gitignore` به تنهایی مانع خواندن یا ارسال داده نمی‌شود. هیچ مخزنی در این مرحله ساخته نشد.
