# بستهٔ اجرایی بررسی آفلاین Sync شفاخانه

این بسته برای مرحلهٔ فنی بررسی و آماده‌سازی است. هدف نهایی Sync هنوز تکمیل‌شده نیست؛ تطبیق آنلاین و آزمایش واقعی قطع‌و‌وصل انترنت بعد از برگشت نتیجه انجام می‌شوند. فایل اجرایی به هویت واقعی شفاخانه محدود است و نصب دفتر را به جای منبع شفاخانه ثبت نمی‌کند.

## کار کارمند شفاخانه

۱. فایل `AlShifa-Sync-SafeReview.exe` را به کمپیوتر اصلی شفاخانه انتقال دهید. وقتی ثبت جاری ندارید و کارهای باز ذخیره شده‌اند، آن را اجرا کنید و پیام Administrator ویندوز را تأیید کنید.

۲. دکمهٔ «شروع بررسی و بکاپ امن» را بزنید. برای بکاپ یکپارچه، API شفاخانه مدت کوتاهی متوقف می‌شود؛ MySQL اصلی متوقف نمی‌شود. پس از تهیهٔ بکاپ و شواهد یکپارچه، API پیش از آزمایش بازیابی دوباره راه‌اندازی می‌شود. بسته را تا پایان نبندید.

۳. فقط فایل با پسوند `.alshifa-review` داخل پوشهٔ `AlShifa-Sync-Return-...` کنار فایل اجرایی را به دفتر برگردانید. این فایل رمزگذاری شده است. پوشهٔ بکاپ خصوصی، `secrets`، SQL یا لاگ را انتقال ندهید. اگر نوشتن کنار EXE ممکن نیست، ابتدا خود EXE را به پوشه‌ای قابل‌نوشتن مثل Desktop انتقال دهید.

این مرحله به SSH، VPN، تنظیم URL، کپی کلید Sync یا اجرای دستور دستی نیاز ندارد. فایل اجرایی از runtime موجود ویندوز و MySQL همان نصب استفاده می‌کند و بستهٔ دانلودی تازه نصب نمی‌کند. اگر بررسی هویت، مسیر، تنظیمات یا فضای دیسک شکست بخورد، متوقف می‌شود. فایل اجرایی امضای ناشر Authenticode ندارد؛ hash آن همراه بسته تحویل می‌شود.

## بررسی‌های بسته

- شناسایی مسیر واقعی سرویس‌های `AlShifaApi` و `AlShifaMySQL`، هویت نصب، دیتابیس `alshifa`، پورت، datadir و UUID واقعی سرور؛ تشخیص مسیرهای reparse و overrideهای تنظیمات. هیچ تغییر تنظیمات شبکه یا سرویس نصب‌شده انجام نمی‌شود.
- الزام برقرار بودن `RequireCompatibilityApproval=true`، بررسی schema، نسخهٔ runtime و hash فایل اجرایی/DLL نصب‌شده. بسته hold را برنمی‌دارد.
- تهیهٔ بکاپ تازهٔ دیتابیس و کپیِ تأییدشدهٔ فایل‌های app، keys، secrets و storage در پوشهٔ خصوصی جدید زیر `sync-review-backups`؛ هیچ بکاپ قبلی جایگزین نمی‌شود. بکاپ محلی روی همین دیسک برای بازگشت فنی است و جای بکاپ مستقل بیرونی شفاخانه را نمی‌گیرد.
- اثبات ثبات تمام ردیف‌ها هنگام بکاپ و جمع‌آوری seq/ack/snapshot، شمار و اثرانگشت کل صف، کلیدهای هش‌شدهٔ اقلام صف، و metadata رسید دقیق دو درخواست قدیمی. هیچ بدنهٔ فرمانی اجرا نمی‌شود.
- جمع‌آوری اثرانگشت HMAC ردیف‌ها و کلیدهای جدول‌های نگاشت‌شده در مدل فعلی، با حذف ستون‌های هویتی محرمانه، ستون‌های generated و جدول‌های داخلی خارج از Sync. اطلاعات خام مریض و مبلغ مالی در فایل برگشتی نیست. کلید HMAC همین اثرانگشت‌ها فقط داخل نتیجهٔ رمزگذاری‌شده برمی‌گردد و کلید عملیاتی Sync نیست.
- بازیابی واقعی بکاپ روی یک فرایند مستقل MySQL با datadir تازه، UUID متفاوت، پورت تصادفی loopback و رمز تصادفی؛ پورت ۳۳۰۸ برای این clone ممنوع است. هویت PID و محدودبودن listener به `127.0.0.1` پیش از import کنترل می‌شود. هیچ API روی دیتابیس بازیابی‌شده اجرا نمی‌شود؛ event scheduler خاموش است.
- تطبیق ستون‌ها، indexها، روابط، شمار و hash تمام ردیف‌ها پس از بازیابی؛ بررسی توازن Ledger و فایل‌های attachment؛ ثبت فهرست بکاپ‌های قدیمی برای بررسی سابقه. بکاپ‌های قدیمی به‌طور خودکار روی نصب اصلی بازیابی نمی‌شوند.
- آزمایش دسترسی معمول HTTPS به صفحهٔ ورود آنلاین با اعتبارسنجی عادی TLS، بدون امضای Sync، batch یا فراخوانی فرمان. نتیجهٔ آفلاین بودن هم در گزارش قابل ثبت است.

داده و clone خصوصی حذف نمی‌شوند؛ clone بعد از آزمایش متوقف می‌شود. فقط فایل موقت مجوز اتصالِ ساخته‌شده توسط همین اجرا حذف می‌شود. بسته سرویس یا Scheduled Task تازه‌ای نصب نمی‌کند، تنظیمات Sync را نمی‌نویسد، sourceId و seq/ack را تغییر نمی‌دهد و صف را خالی نمی‌کند.

## حفاظت و ادامهٔ کار در دفتر

نتیجه با RSA-OAEP-SHA256 و AES-256-CBC به همراه HMAC-SHA256 رمزگذاری و احراز تمامیت می‌شود. کلید خصوصی بازکردن نتیجه با DPAPI و ACL روی کمپیوتر دفتر محفوظ است و در EXE یا USB نیست. کلید خصوصی گیرندهٔ بستهٔ اتصال آینده نیز با DPAPI و ACL روی شفاخانه باقی می‌ماند؛ عمومی آن داخل نتیجهٔ رمزگذاری‌شده برمی‌گردد. این کلید انتقال است و به معنی صدور کلید Sync نیست.

در دفتر، ابزار `scripts/open-hospital-sync-review.ps1` فقط نتیجه را به مسیر حفاظت‌شده باز می‌کند و هیچ فعالی انجام نمی‌دهد. بعد از دریافت نتیجه، موارد زیر باید ادامه یابند: تطبیق خصوصی ردیف‌ها و کلیدهای صف با آنلاین؛ بررسی منشأ سابقه و برخورد شناسه‌ها؛ بازیابی/آشتیِ بررسی‌شدهٔ سابقهٔ seq/ack در صورت نیاز؛ حفظ توقف دو درخواست قدیمی؛ ثبت منبع و کلید با نگه‌داشتن hold؛ سپس فعال‌سازی کنترل‌شده فقط پس از عبور از بررسی تکرار و سازگاری.

تعداد ۶۵۲۳ مربوط به گزارش قبلی است؛ بسته شمار جدید را در زمان اجرای خودش می‌خواند. تغییر شمار به معنی اجازهٔ حذف یا انتقال نیست. علامت `success` در نتیجه، موفقیت جمع‌آوری و بکاپ را نشان می‌دهد؛ اجازهٔ enrollment یا انتقال نیست. بسته حتی در صورت موفقیت تمام بررسی‌های محلی نیز Sync را فعال نمی‌کند.

آزمایش عملی نهایی رفت‌وبرگشت، قطعی واقعی انترنت، ادامهٔ کار محلی و بازیابی خودکار بعد از اتصال باید روی نصب واقعی اثبات شود. نتیجهٔ آزمایش ساختگی دفتر جای آن را نمی‌گیرد.
