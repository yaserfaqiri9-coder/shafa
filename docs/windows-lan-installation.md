# نصب یک‌باره سرور الشفا و اتصال کارمندان با لینک

آدرس داخلی تأییدشده: **https://lan-shafa.novatechsoft.com/login**

آدرس آنلاین و Sync همان **https://shafa.novatechsoft.com** می‌ماند. این دو نام را در DNS داخلی به یک سرور تبدیل نکنید.

## قبل از نصب؛ فقط یک‌بار توسط مسئول شبکه

1. IP داخلی کمپیوتر سرور و MAC کارت شبکه آن را پیدا کنید. در روتر، DHCP Reservation بسازید. `192.168.1.20` فقط مثال است؛ از IP واقعی سرور استفاده کنید.
2. در DNS داخلی روتر یا Windows DNS، رکورد A به شکل `lan-shafa.novatechsoft.com → IP سرور` بسازید. DHCP شبکه و Wi-Fi باید همین DNS داخلی را به دستگاه‌ها بدهد؛ DNS عمومی را به‌عنوان DNS دوم کلاینت قرار ندهید. در صورت استفاده از IPv6، DNS توزیع‌شده آن نیز باید داخلی باشد.
3. شبکه کارمندان باید اجازه اتصال به سرور روی TCP 443 را داشته باشد. Wi-Fi مهمان یا Client Isolation نباید مانع دسترسی کاربران مجاز شود. هیچ پورت WAN یا MySQL را به بیرون باز نکنید.
4. در Cloudflare برای **فقط zoneِ novatechsoft.com** یک API Token با **Zone / DNS / Edit** و **Zone / Zone / Read** بسازید. نیازی به Global API Key، تغییر رکورد آنلاین، Proxy/Tunnel یا A عمومی برای آدرس داخلی نیست. صدور گواهی با TXT موقت `_acme-challenge.lan-shafa.novatechsoft.com` انجام می‌شود.
5. یک ایمیل مسئول گواهی آماده کنید. سرور هنگام صدور و پیش از انقضای گواهی، به HTTPS خروجی Cloudflare و Let's Encrypt نیاز دارد. Windows باید ریشه‌های عمومی معتبر و ساعت صحیح داشته باشد.

اگر از Windows DNS استفاده می‌کنید، مسئول DNS می‌تواند یک zone فقط برای `lan-shafa.novatechsoft.com` و رکورد A با نام `@` و IP سرور ایجاد کند. ایجاد این zone نباید zone عمومی `novatechsoft.com` را جایگزین کند. نقش DNS و تنظیم DHCP توسط مسئول شبکه انجام می‌شود؛ نصب‌کننده کارت شبکه، DNS عمومی یا روتر را خودسرانه تغییر نمی‌دهد.

## نصب تازه روی Windows Server

1. از بسته جدید، `Install-AlShifa.exe` را **فقط روی سرور** با Administrator اجرا کنید. رابط گرافیکی به Windows Server 2019 یا جدیدتر با Desktop Experience نیاز دارد.
2. IP رزروشده، رمز مدیر و دیسک Backup را انتخاب کنید. گزینه «اتصال با لینک امن» روشن بماند. آدرس داخلی بالا، ایمیل و Token محدود Cloudflare را وارد کنید و شرایط صدور گواهی را مطالعه و تأیید کنید.
3. نصب‌کننده MySQL خصوصی، API، Firewall شبکه، Backup و بازیابی آزمایشی، گواهی معتبر و تمدید روزانه/پس از روشن‌شدن را تنظیم می‌کند. Token فقط روی سرور، با DPAPI و دسترسی SYSTEM/Administrators نگهداری می‌شود. هیچ پوشه اتصال یا گواهی برای کارمندان تولید نمی‌شود.
4. اگر Windows به Visual C++ Runtime نیاز داشت، فایل رسمی Microsoft با نام `vc_redist.x64.exe` را کنار نصب‌کننده روی **سرور** قرار دهید؛ نصب‌کننده امضای آن را بررسی و خودکار نصب می‌کند. فایل Runtime به‌دلیل شرایط بازتوزیع، پیش‌فرض داخل بسته قرار ندارد.
5. رمز بازیابی Backup را خارج از سرور نگهداری کنید. سپس لینک داخلی را روی یک موبایل معمولی بدون نصب گواهی باز کنید، با یک حساب کارمند وارد شوید و با قطع WAN، عملیات محلی را بررسی کنید. بعد از Restart سرور نیز همین بررسی را تکرار کنید.

پکیج شامل دیتابیس توسعه یا مریضان نیست. روی سرور دارای اطلاعات، «نصب تازه» اجرا نکنید؛ از گزینه Update موجود با Backup و بازیابی آزمایشی استفاده کنید.

## نصب موجود؛ فعال‌سازی لینک معتبر پس از Update

بعد از آماده‌بودن DNS داخلی و نصب نسخه جدید، PowerShell را روی همان سرور با Administrator باز کنید:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\AlShifa\scripts\prepare-trusted-lan.ps1 -Activate -LanIp 192.168.1.20 -Email your-email@novatechsoft.com -AcceptAcmeTerms
```

IP و ایمیل مثال را عوض کنید. Token را فقط در ورودی امن همان پنجره وارد کنید؛ آن را در فرمان یا چت ننویسید. اگر صدور شکست بخورد، سرویس و اطلاعات قبلی حذف نمی‌شوند؛ مشکل DNS، دسترسی Token یا انترنت سرور را رفع و همین فرمان را دوباره اجرا کنید. شرایط ACME: https://letsencrypt.org/repository/

کنترل نصب بدون نوشتن داده:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\AlShifa\scripts\test-lan-access.ps1
```

این کنترل DNS، اعتماد عادی HTTPS، سلامت API/دیتابیس، صفحه ورود، manifest، آیکون‌ها، service worker و رد دسترسی بدون ورود را بررسی می‌کند. هیچ Certificate به Trust Store اضافه نمی‌کند. وضعیت تمدید در `C:\AlShifa\tls\status.json` و Task Scheduler با نام `AlShifa Certificate Renewal` دیده می‌شود. پوشه‌های `tls` و `certs` اطلاعات محرمانه سرورند؛ به کلاینت‌ها منتقل نشوند. در انتقال به Windows جدید، Token باید دوباره وارد شود چون DPAPI به همان ماشین وابسته است.

## کارمندان؛ بدون فایل و گواهی

- **Windows:** اتصال به شبکه شفاخانه → بازکردن لینک داخلی در Edge/Chrome → Install app.
- **Android:** اتصال به Wi-Fi شفاخانه → بازکردن لینک در Chrome → نصب برنامه یا Add to Home Screen.
- **iPhone:** اتصال به Wi-Fi شفاخانه → بازکردن لینک در Safari → Share → Add to Home Screen.

آیکون `/login` همین سرور محلی را باز می‌کند. حساب، صلاحیت و نشست هر کارمند مستقل است؛ ورودِ معتبر موجود می‌تواند او را مستقیم به صفحه مجاز خودش ببرد. اینترنت خارجی برای عملیات LAN لازم نیست؛ اتصال به سرور محلی لازم است. اگر Private DNS یا Secure DNS روی گوشی DNS شبکه را دور می‌زند، آن را برای شبکه شفاخانه روی DNS داخلی تنظیم کنید.

تمدید گواهی قبل از انقضا به انترنت سرور نیاز دارد؛ قطعی انترنت، تا زمانی که گواهی معتبر است، کار محلی را متوقف نمی‌کند. Sync دوطرفه و صف دائمی آن نیز جداگانه حفظ می‌شوند.

صدور واقعی گواهی، تغییر DNS روتر، نصب سرویس در Windows Server واقعی و پذیرش روی دستگاه فیزیکی در محیط توسعه اجرا نشده‌اند؛ اجرای این مراحل در محل لازم است.
